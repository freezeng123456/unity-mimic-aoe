调研日期：2026-10-04。代码基线：`d65ae3d`（0.3.2）。本文是重制设计与代码审查结论，不是已经完成的视觉验收记录。

本轮没有找到足够的一手资料，能够证明英国、荷兰、法国、奥斯曼在原作中各自拥有所有通用建筑的独立模型。以下六套体系是依据上述视觉方法制定的**本项目原创方向**，不是原作建筑清单或逐个资产的复刻声明。没有采用官方论坛玩家提案作为官方设定。

## 当前画面与缺口

已实际观看 `outputs/frontier-reckoning-demo-059` 中法国经济、法奥攻城、奥斯曼经济三张原生截图；它们来自先前 0.3.1 自动对战，而非本次新客户端。审查的 0.3.2 代码仍与这些画面的主要建筑特征一致。

1. 法国和奥斯曼的城镇中心都是同一棕色大双坡屋顶，文明身份主要靠专属兵和一座清真寺表达。通用城镇中心、民居、军营等没有读取玩家文明。
2. 屋面是连续纯色平面，缺少瓦行、脊瓦、檐板、排水与烟囱穿屋面连接；长距离看仍像基本几何体。
3. 门窗是贴在墙上的小色块，没有窗洞暗部、窗套厚度、窗台、玻璃/木材区分。墙面与屋顶缺少材质尺度与老化分布。
4. 已有市场货摊、马厩栏杆、军营武器架、工坊吊臂、驿站院落、清真寺穹顶，功能轮廓有可保留的基础；重制应加强这些特点，而非所有建筑一律增加塔尖。
5. 基础地台过于完整且颜色单一，建筑像放在地图上的棋子。需要墙脚暗部、入口铺地、受控的地面边缘变化，但不能因此扩大实际堵路范围。
6. 球形树冠、简单矿石与缺少细节的马匹/人物也会限制整体观感。建筑重制不能单独证明“全面升级建模”完成；角色、坐骑、火炮、资源和环境的近景与实机还需另行验收。

## 六种建筑语言

颜色是材料固有色；红蓝队色另置于旗帜、门楣织物、百叶窗或少量盾徽。六文明在相同队色下也必须可区分。

| 文明 / 规则 ID | 屋顶与体块 | 立面与开口 | 构造和材料细节 | 核心识别点 |
| --- | --- | --- | --- | --- |
| 英国 / `coast` | 陡双坡、交叉山墙、成对砖烟囱；城镇中心采用主厅与较窄钟楼/入口体块 | 暖红砖或浅灰泥配深木框；清晰的白色窗套、竖向窗格、门上过梁 | 脊瓦、檐板、砖拱门楣、烟囱压顶、入口石阶；砖墙低部轻微潮痕 | 民居有庄园住宅气质，屋顶和烟囱占主要识别面积；不能仅比通用 house 多一面旗 |
| 荷兰 / `river` | 紧凑高立面、阶梯山墙、窄深屋体、橙褐瓦顶；银行强化中轴山墙 | 深红砖、浅色水平石带、窄高窗、拱形入口，竖向节奏明显 | 山墙压顶与分段台阶、石窗台、装卸横梁、木百叶、金属拉杆；银行用厚石基座和独立金属门 | 阶梯山墙加红砖为文明识别；银行用金库入口和贸易标识维持功能识别 |
| 法国 / `france` | 蓝灰石板、折坡/高髋屋面、老虎窗；城镇中心对称主楼与侧翼 | 暖白石灰岩、深色凹窗、规整窗套、突出入口；庭院建筑可用拱廊 | 转角石、水平檐口、老虎窗三角帽、石台阶、少量铁栏和成对烟囱；石板有受控色差 | 石板屋顶与暖白石墙的大面积对比；从顶视角也须区别英国棕顶与荷兰阶梯山墙 |
| 奥斯曼 / `ottoman` | 暖石低体量、庭院、连拱廊；行政/宗教建筑用穹顶，民居可用低坡瓦顶和突出檐口 | 浅砂色墙、深色拱形开口、细长窗、带厚度的窗格；避免每栋建筑都做成清真寺 | 拱券分块、柱头、窗框与檐口、穹顶基座和分缝；铜灰/青灰穹顶与少量釉色装饰；仅清真寺配置宣礼塔 | 城镇中心靠院落与拱廊，清真寺靠穹顶+细塔，市场靠遮阳摊位；宗教与军事功能不得混同 |
| 行旅 / `wayfarer`，原创 | 低矮平顶、连续院落、阶梯屋面、可拆遮阳架 | 沙色灰泥、深木门、窄通风口、靛蓝布棚；用阴影与开口形成厚墙感 | 木梁端头、绳索、滚边帆布、驿站货架、货箱/陶罐；墙脚风化与布料轻微褪色 | 中庭、遮阳布和运输设施；不要照搬奥斯曼的穹顶与宣礼塔 |
| 高地 / `highland`，原创 | 紧凑低体量、厚粗石墙、陡灰石板顶、宽烟囱；工坊保留外露吊臂 | 不规则灰石与深木横梁，小而深的窗、厚门套，承重逻辑清楚 | 外露木撑、铁铰链、石墙压顶、屋面重叠板、堆料和工具；少量苔色集中于墙脚而非整栋泛绿 | 石屋+木撑的稳重体量，工坊的吊臂/加工平台在远镜头可见；不能只是英国模型换灰色 |

各文明既共享一个制作工具链，也有真正不同的屋顶网格和立面构造。材质变色只能作为补充，不能作为六套模型的完成证据。

## 所有已实现建筑的覆盖

基线 `Assets/Resources/Rules.json` 含 14 类建筑。十类通用建筑需要按所属玩家文明换形；四类专属建筑只按自己的文明制作，但与该文明通用建筑保持一致。

| 类别 | 必须保留/强化的功能表达 | 细节重点 |
| --- | --- | --- |
| `town` 城镇中心 | 最高的民政主楼、明确主入口、带队旗的集结识别 | 主副体量、门廊/庭院、钟楼或文明对应行政标识；不能依赖文字标签识别 |
| `house` 民居/英国庄园 | 低于城镇中心的居住轮廓 | 烟囱、窗、台阶、小檐棚；英国庄园的住宅身份明显 |
| `barracks` 军营 | 长厅、训练场、武器架 | 门洞、训练靶、撑架、院墙收边，部队出口必须清楚 |
| `stable` 马厩 | 开口棚、分栏、饲料/饮水设施 | 看得见柱梁与棚顶底部，门口不能用视觉实墙封住 |
| `foundry` 铸炮厂 | 烟囱、炉口、厚工业厂房 | 砖石耐火底座、金属炉门、车轮/炮管生产道具；发光只集中于炉火 |
| `market` 市场 | 连续遮阳棚、货摊、仓储 | 有厚度的布边、支杆、货物类别、门廊；保留队色可见面 |
| `tower` 瞭望塔 | 垂直轮廓、顶部观察层 | 实际支撑、射口、栏板、顶部文明轮廓；血条不得埋进屋顶 |
| `farm` 农田 | 整齐但非完全同高的耕作行 | 土垄、边界、工具或小型灌溉设施；不做遮挡所有工人的大建筑 |
| `estate` 庄园经济设施 | 计账主屋与经济作物/设施组合 | 小型办公门廊、账房/仓储道具和田畦，区别普通民居 |
| `trade_post` 贸易站 | 装卸平台、货仓、道路接口 | 货箱绑带、棚架、地面接缝；保持原道路和交易插槽语义 |
| `bank` 荷兰银行 | 阶梯山墙、厚基座、受保护入口 | 金库门、窗栏、贸易徽章，不能像平顶碉堡 |
| `mosque` 奥斯曼清真寺 | 穹顶、礼拜厅、入口连廊、宣礼塔 | 拱券、檐口、穹顶座、塔身环廊及顶饰的真实连接 |
| `waystation` 行旅驿站 | 中庭与三面住宿/储货空间 | 廊架、布棚、货物、木门和屋檐；保留开放院落 |
| `workshop` 高地工坊 | 加工厅、吊臂、装卸场 | 斜撑、滑轮、铁件、工作台、木石堆料；保留可读的吊臂 |

## 时代发展与材料

时代差异要从现有玩家 `age` 得到，既有建筑升级后也要更新。主入口、占地和基本建筑用途在升级前后保持稳定；装饰增加必须服从承重与功能。

| 时代 | 可见发展 | 不宜采用的捷径 |
| --- | --- | --- |
| I 边疆 | 完整但朴素的本文明基本构造，木/灰泥与较少开口，基础门廊/檐口 | 一个未完成的盒子；通过缩小整栋建筑假装早期建筑 |
| II 商业 | 增加石基/砖带、规整窗套、市场棚边或住宅烟囱等文明细节 | 只变亮颜色 |
| III 要塞 | 加强转角石、主入口与侧翼，更完整屋面、檐口和功能设施 | 不分功能地给所有建筑加塔 |
| IV 工业 | 材料工整度提高，民政建筑更成熟；生产设施增加金属构件和工业烟囱 | 给清真寺和住宅都装工业烟囱 |
| V 主权 | 终期檐口、门廊、天窗/栏板、饰顶或仪式旗组；仍保留本文明屋顶大形 | 以整体放大、金色涂满墙面或极高尖顶代表高级 |

建筑间允许复用成熟部件；必须在近景和正常镜头中记录每次有意义的时代变化。尚未合法解锁的建筑，模型检查可用明确标注的展示场景，不能伪装为正常支付建造结果。

材料至少区分灰泥、砖、砌石、木材、瓦/石板、金属、布料、玻璃。为每类准备统一真实尺度：砖缝与木纹不能随着建筑缩放变成手掌大小或汽车大小。屋面表面方向沿坡面，瓦行沿檐口排列；转角、山墙、窗洞不能让纹理跨面拉伸。粗糙度和法线/高度细节应与材质一致，石灰墙不能像塑料，铁件不能与布料一样平。旧化集中在烟道上方、墙脚、窗台下方、屋面接缝和人流入口，避免全表面均匀噪点。

可用程序化生成的原创贴图和合并网格达到这些要求；是否经过某个 DCC 软件不是质量证据。判断依据是最终渲染中的轮廓、结构、材质尺度和细节。

## 当前代码集成风险

下列位置以 `d65ae3d` 为审查基线；实施后需要重新核查，不能把此处的问题自动视为仍存在。

1. **文明信息入口。** `ProceduralArt.BuildEntity(EntityState, Transform)` 没有 `World`、玩家文明或时代参数。通用 `EntityDef.civilization` 为空；不能从它推断法/英/奥建筑。`WorldView.Acquire` 应从有效 owner 对应的 `PlayerState.civilization` 和 `age` 取得样式；中立资源与无玩家 owner 必须有确定回退。保留方便纯模型测试的入口，但不能让旧入口默认覆盖实机文明。
2. **对象池串文明。** `WorldView` 的池键为 `def.id + "_" + owner`，`ResetWorld` 会保留池。相同玩家槽从法国换奥斯曼时，会复用旧模型。池键/视觉签名必须包含文明与时代，且升级后对已显示和暂时被迷雾隐藏的建筑都有效。重建应复用仿真实体 id，不能重置订单、HP、施工或集结点。
3. **隐藏信息。** 不可因为敌方建筑升级了视觉就穿透迷雾。继续遵守 WorldView 的 `IsVisible`。回到可见状态再取对应样式，并避免在不可见建筑位置播放暴露情报的效果。
4. **点击体积。** `EntityPickGeometry.WorldBounds` 合并所有子 Renderer 的 AABB。大幅外伸的旗、货物和塔会扩大命中范围；需要实机验证轮廓点击、建筑旁边点地移动、多人围攻和被建筑遮住的单位。缩放施工模型、时代重建、对象池恢复后都应使缓存 bounds 失效。
5. **占地与通行。** 当前建筑模型一般以规则宽深的 0.44 倍作为半尺寸。结构和实体支柱应落在合法占地之内；少量悬挑屋檐可外伸，但不能做出视觉实墙堵住仿真可走的门口/院道。模型升级不改变 Rules 的占地、导航、交互距离或出兵点。
6. **血条高度。** 当前所有建筑血条固定在 y=5。新塔、钟楼或宣礼塔可能超出，应依据模型实际 bounds 顶端定位，并保留屏幕方向一致性。不要把健康条纳入模型 bounds 导致递归增高。
7. **Draw call 与资源生命周期。** `ProceduralArt.Part` 每小块创建一个 GameObject/Renderer；单靠堆数百砖块将影响实机。建议细节用原创材质与合并网格，少量真实结构保留独立件。合并后要销毁临时 owned mesh，正确管理共享材质/贴图；重复开局和时代切换应检查资源数量有界。
8. **旧测试与实际目的。** 现有 `ClassicCivilizationArtTests` 要求清真寺指定名字子物体有 MeshFilter；`CivilizationExpansionArtTests` 要求驿站/工坊指定结构且 Renderer 数大于 15。若改为合批，应以实际网格结构、形状、语义标记和渲染证据替代 Renderer 数量；不要为了满足旧计数保留无用小渲染器。
