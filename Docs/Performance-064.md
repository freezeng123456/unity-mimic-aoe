# 呈现更新与原生性能测量

本轮针对 0.6.0 原生报告中的长帧和分配补充呈现优化与测量。当前 0.7.0 已取得普通经济 F8 和两组原生压力报告，见[普通窗口](Evidence/064/Native/Normal/README.md)与[压力原始材料](Evidence/064/Native/Benchmarks/README.md)。200/400 陆军加 12 船的 P95 分别为 17.0631/32.5467 ms；400 组仍有 116.479 ms 最大帧，不能宣称稳定 60 FPS。

0.6.0 的相同地图、军队、机型、分辨率与 Development / Mono 配置曾记录 P95 66.5009/75.3379 ms，保留为历史参照；两版运行属于不同时间的独立样本，未作多轮随机顺序 A/B 或统计显著性检验。旧仿真字段受组件采样顺序影响，导航/战斗/经济值重复读取最近一次 Tick；不能与新字段直接计算系统 CPU 改善比例。

## 当前原生结果

两组均为 Apple M3 Pro、36 GB、Unity 6000.6.3f1、macOS arm64 Development / Mono，GUID `48cbcf92c92f409c945f83eeb9b8d500`；1600×1000，`winding`，seed 314159，镜头 orthographicSize 26，60 FPS 上限、vSync 关闭。总活动约 90 秒，其中前 10 秒预热，测量窗口约 80 秒；串行运行，无暂停、无并行 Editor/测试/压缩。两端 F9 证明预热期及结束时在前台，测量期间没有工具切换窗口；未连续采样焦点，不能声称有逐帧焦点检测。

压力夹具直接生成高生命值混合军队，防止数量衰减，并反复下达跨桥/水路攻击移动；它不能证明普通战争中的军队存活、经济平衡或 412 个单位同时在屏幕内。Render Thread 计数均不可用（-1、0 可用样本），不解释为零渲染开销。初次启动含测量期后台区间的两组预试只保留在本地 `Pilots`，未混入最终归档。

普通经济 F8 为 I 时代小规模采集画面，约 88.43 秒、5264 帧、884 模拟步，P95/P99 17.378464/17.605961 ms、最大帧 33.309082 ms。它不满足 300 秒长窗口；下述 16× 正常规则 AI 对局也不用于普通速度 FPS 结论。

当前日志仍记录退出时的 `prematurely finalized` / `MemoryLeaks` 遥测；这只是已观察的关闭现象，未定位根因或验证实际泄漏。预热长帧、400 组长尾、分配与长期堆增长仍需后续定位，20–40 分钟战争/水战、Release 与跨平台尚未验收。

## 已修改的实际路径

- `UnitAnimation.Apply` 对相同骨骼姿态复用上次结果；静止姿态忽略未使用的行走相位，移动、装填、盾姿、武器模式、货物和工具变化仍刷新。显式恢复初始姿态会使缓存失效。采篮的世界朝向变化也会刷新。
- `WorldView` 对镜头外且未选中的单位每 0.2 秒刷新骨骼，镜头采用额外 15% 的边界以涵盖马匹、船首和阴影。进入镜头或成为选中对象当帧刷新。根位置、健康、单位指令、迷雾和拾取继续正常更新；没有停用镜头外实体或模拟。
- 同一帧复用地表高度结果；隐藏血条和未选中圈不重复写属性，不变的活跃状态不重复调用 `SetActive`。
- `RtsInput` 移除每次曲桥拾取的四元素数组和逐帧选择清理谓词。悬浮拾取复用结果，但指针、相机矩阵/像素区域、船只选择域或 World 变化会使缓存失效。真实点击始终重新求交。

## 测量范围

`RuntimeBenchmark` 在 `LateUpdate`、执行顺序 1000 采样，位于正常模拟与呈现更新之后。`measuredSimulationSteps` 记录实际固定步数；没有步进的帧不复用旧仿真耗时。`simulationPerRenderedFrameMs` 为所观察 `AdvanceFrame` 调用耗时的每帧平均。导航/战斗/经济的旧字段仅在发生步进的帧采样，并由 `tickSampleFrames` 作为分母；一次捕获追赶多个 Tick 时，这些仍只覆盖最后一个 Tick，不能解释为每个 Tick 的精确均值。

两种捕获都使用 `GC.GetTotalMemory(false)`，不调用强制 GC。GC0/1/2 差值、托管堆快照、Unity 已分配内存是不同口径，不能相加或据此认定泄漏。F8 记录每秒事件总数，可协助区分比赛历史增长与释放问题；本轮没有擅自截断事件历史。

可用时，`ProfilerRecorder` 记录 `GC Allocated In Frame`、`Main Thread`、`Render Thread`、`Draw Calls Count` 和 `Triangles Count`。不可用值为 -1，并保留对应可用样本数；不将缺失当作零开销。它们是观察时最近完成的 Profiler 样本，可能滞后，不能直接把某次分配对应到当前帧。Unity 的每帧 GC 分配计数和 `LastValue` 语义见 [Memory Profiler](https://docs.unity3d.com/6000.3/Documentation/Manual/ProfilerMemory.html) 与 [ProfilerRecorder.LastValue](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Unity.Profiling.ProfilerRecorder.LastValue.html)。记录器在观察结束时释放，记录缓冲在开始时分配，捕获开销本身包含在原生帧区间中。

`WorldView.LastFrameMs` 包含该组件的呈现 CPU 工作，`LastFogMs` 是其中更新迷雾/小地图的 CPU 区间；二者不包含 GPU 时间，也不应相加。姿态应用数、镜头外跳过次数与带边界的镜头相关单位数用于检查降频是否实际发生；后者不同于屏幕内单位中心数量。

## 验收方法

新增回归检查真实炮轮/炮管恢复、盾与武器切换、镜头重入即时姿态、镜头不揭开迷雾、呈现不改变单位位置/命令/生命，以及相机/船只/世界切换后的拾取缓存失效。捕获回归检查无步进帧不重复旧 CPU 数值，缺失 Profiler 计数不生成虚假的可用零样本；原暂停测试按照 Update 与 LateUpdate 完整调度执行。

原生比较固定机型、分辨率、地图、种子、军队、镜头、帧率上限和活动时长，单独报告预热与测量窗口；同时保留实际步进数、P95/P99、最大帧、超过 50/100 ms 的帧数、分配样本和呈现耗时。200/400 压力样本与正常经济/战斗窗口分别统计。Development 和 Release 的结果应分别标注，不能混用；当前数据仍不足以宣称 GC 或长帧问题已全部解决。
