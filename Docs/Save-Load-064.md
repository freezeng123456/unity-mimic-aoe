# Local saved matches (0.7.0 candidate)

The previous SaveReport was a diagnostic report, not a checkpoint. The new system writes three local save slots under the existing game's persistent data directory (`Saves/slot-1.json` through `slot-3.json`). Pause → Save Match chooses a slot; main menu or pause → Load Match restores it and starts paused so commands cannot run during loading. Choosing an occupied slot explicitly replaces that checkpoint.

A saved match contains authoritative entity/player scalar state, current and queued orders, paths and navigation versions/layers, production/research/age queues and paid/reserved population, rewards and shipments, projectiles, resources and economy ledgers, all explored/visible fog cells, treasure/trade/caravan/discovery state, pending garrison evacuations and income-log buckets. Fine recovery waiting states are included in the continuation acceptance described below. Industrial wagon deployments, factory construction, production mode and artillery progress use the same checkpoint mechanism. AI enemy memory, decision/attack/age/search/naval/manufacture clocks and fixed-step accumulator/step count are retained, including original controller dispatch and enemy-memory order.

Camera focus/zoom, selection, control groups and audio switches are restored. Pointer presses, drag/placement gestures, playback audio and transient performance samples are reset. Old events are retained as evidence but skipped by the resumed audio cursor. Restored selections/groups are filtered by live ownership/visibility rules. Loading from an active match first validates and reconstructs the candidate; invalid saves leave the current match intact.

Format: explicit schema 1 DTOs; shared entity definitions are linked by their definition ID strings, rather than embedded per actor. Readonly queues/sets/dictionaries are copied to arrays because Unity JsonUtility cannot serialize those containers as authoritative state. SHA-256 checks the serialized payload for incomplete/damaged files; a rules fingerprint rejects saves created with a different rule catalog. This checksum detects corruption and is not an authentication/anti-cheat system. App version is recorded and the native load path requires an exact application-version match, including when the rules are unchanged. Later compatibility can be widened only through an explicit tested migration; code changes that alter resume semantics must also increase the schema.

Writes flush a unique temporary file and atomically rename/replace the slot. A failed write retains the previous slot, deletes only its own temporary file and reports the failure. The supported save limit is 64 MiB. No cloud save or shared-file publishing is added.

The final current-source Unity run `run-LOUCjHNW` passed 796/796 tests (466 EditMode and 330 PlayMode), archived in [Evidence/064/Tests](Evidence/064/Tests/README.md). Save coverage includes six authored maps, four classic civilizations, queued production and ship arrivals, incomplete construction, ongoing naval projectiles, garrisons/fog history, detached snapshots, AI/accumulator equivalence, atomic overwrite and damaged/mismatched/invalid state. PlayMode exercises the real GameController component in the Editor through the menu boundary and restores camera/input/groups; it is separate from native Player execution. Test saves use an isolated temporary directory so they do not overwrite player slots.

Fine recovery capture, restoration and validation also preserve waiting entries with no active UnitOrder. `ImplicitPursuitKeepsItsNullOrderRecoveryQueueAndColdContinuation` passed in the focused `implicit-recovery-final-2` run (1/1) and again in the final full EditMode XML. It lets ordinary implicit pursuit create the FIFO waiting state, without queue injection, then checks cold-restored continuation over 21 simulation ticks. The final evidence binds runtime commit `5cce74ccf7222133af9bad633923f452b100bfb2` and source fingerprint `8342b85bf835fd48d5c4dfc8f612ed64770fc5b7d026d96c4f539caaa96d79b0`.

[Native/Normal](Evidence/064/Native/Normal/README.md) separately records the final client's ordinary age-I match: save slot 1, overwrite it, exit the process, launch a new process, load through the menu, and re-save a byte-identical checkpoint. World/AI/queues, fixed-step state, camera, selection/groups and audio settings match; resumed production creates a real settler and public Gather input continues the economy. Its build GUID is `48cbcf92c92f409c945f83eeb9b8d500`. This native case does not cover a forced interruption during a slot write, all keyboard combinations, or a natural ended match.

[Native/Industry](Evidence/064/Native/Industry/README.md) records four additional controlled industrial loads and actual F9 pairs. Their `fixtureScope` explicitly controls age IV, XP and a two-card industrial deck with no AI; their `nativeScope` is actual final-client rendering, artillery selection and the recorded British factory-mode changes. They do not establish normal-opening industry progression. The temporary managed preview slot 3 was removed after verification; the ordinary slot 1 and continued slot 2 were independently checked against their archived hashes. Final packaging and cloud delivery still require their own receipts.

Not a multiplayer synchronization or general replay implementation. Initial states and preserved simulation details are useful foundations, but neither event logs nor a checkpoint alone establish deterministic networking.
