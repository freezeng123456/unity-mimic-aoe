# 049 活动声音设计记录

## 定位

本版本加入的是原创运行时合成的开发期反馈音，不是最终录音、最终混音或商业游戏素材。所有 cue 都由 `ActivitySoundClips` 生成：22050 Hz、单声道、非循环、固定独立 `System.Random` 种子，最长 0.27 秒，样本峰值限制在 ±0.7，首末样本为 0。包络现在统一用秒数计算：2 ms attack、20 ms release，并叠加自然衰减；采矿 cue 另加多频共鸣。

| 类别 | 时长 | 基频 | 噪声 / 音调 | 表现意图 |
|---|---:|---:|---:|---|
| Footstep | 0.10 s | 135 Hz | 0.72 / 0.28 | 偏噪声的步伐接触 |
| Hoof | 0.13 s | 205 Hz | 0.38 / 0.62 | 更清晰的低频敲击 |
| Wheel | 0.22 s | 92 Hz | 0.30 / 0.70 | 较长的车轮滚动低响 |
| Woodcut | 0.19 s | 175 Hz | 0.55 / 0.45 | 木质接触与砍伐感 |
| Mine | 0.16 s | 265 Hz | 0.32 / 0.68 | 金属/矿石敲击，附 4.7×、7.1×共鸣 |
| Handling | 0.085 s | 320 Hz | 0.66 / 0.34 | 短促搬运、接触反馈 |
| Build | 0.27 s | 118 Hz | 0.48 / 0.52 | 低频施工敲击；修理复用 |

## 真实行为到声音

`GameController.Update()` 在模拟推进后调用 `Audio.TickActivity()`。`UnitActivityAudio` 每个模拟时间点只采样一次，并从真实实体状态选择一个活动源。移动 cue 需要单位确实处于 `Moving` 且本步有实际位移，按单位类型累计步距；停止、没有位移和重复模拟时间不会产生声音。

工作 cue 需要本帧由经济系统写入 `WorkActivity`，且当前订单仍然是同一目标、同一工作类型。采集只有在实际产生资源收入后才会写入记录；建造只有工人到位并被计入施工者后才会写入；修理只有支付资源并实际增加生命值后才会写入。因此接受订单、缺钱、未完成设施、等待采集位置和没有实际进度都不会冒充工作声。早期诊断中曾把守卫的合法声音误判为村民继续工作；根因已通过 diagnostic 日志定位，并在隔离守卫后的冻结测试中取得旧版 0/5、新版 5/5，不能把该旧误判当作当前村民工作 bug。

## 播放边界与声道

活动源必须同时满足实体存活、非驻扎、玩家当前可见和单位中心点位于摄像机视口内。雾中、屏幕外或后来才揭开的旧活动不会进入播放队列；已播放 cue 在实体离开可见视口后会停止。静音、暂停、胜负结束和返回菜单都会停止或清空活动状态。声道固定为 8 个战斗、2 个活动、2 个通知；活动声道有 `until` 占用时间，所有活动事件另有 0.085 秒的真实时间节流。战斗/通知类别也有各自真实时间节流和容量限制。

当前声道是二维混音：活动声会按屏幕横向位置设置 `panStereo`，但没有距离衰减、遮挡或真正 3D 声学。该选择旨在提供屏幕左右定位；实际可辨识度仍需原生听觉检查，也未实现真正的3D声学。

## 验收状态

代码路径和冻结行为测试覆盖真实移动、实际采集、施工、付费修理、缺钱修理、雾中/屏幕外活动、暂停、静音和重开。仍需在独立客户端中进行原生耳听：确认多单位密集活动时的节奏、8/2/2 声道混合、音量平衡、停止截断是否自然，并决定是否用真实录音或更完整的最终混音替换这些开发期合成 cue。现阶段不宣称完成最终音频交付。
