# 下一轮迭代建议：蜿蜒河谷与港区建模

2026-10-04。历史设计建议，撰写时客户端为 0.5.0；下文保留当时现状与目标。四部分实现现见 [Rivers-063](Rivers-063.md)，最终已验收范围见 [Completion-Status](Completion-Status.md)。本文不是全项验收已通过的证明。

## 目标与现状

建议把下一版 0.6.0 集中在一张可正常对局的蜿蜒河谷图，完成曲河、自然岸坡、港区与船只造型、水面动态和原生演示，再扩展地图与运输玩法。

当前只有固定直河：MapTopology 的水域是 x=57.5–70.5、长128、宽13；WaterPresentation 用矩形水面和两条0.48宽平岸条。两桥、点击桥坡投影、鱼点、AI岸位和巡航路线依赖固定坐标。因此河的死板同时来自几何、地形层次和玩法布局。

当前码头主要是陆地平台与仓库，没有清楚的伸水泊位；船没有船员或推进动作。河、桥、码头、船是程序生成 Mesh，共用程序材质；仅提高贴图分辨率不足以改变轮廓。0.5.0 已有633项自动回归与直河机动样本，但没有完整原生人工体验、原生帧时间或长期内存验收。400陆军+12船的207.7091ms是单次模拟Tick峰值，不能当作渲染FPS。

## 落地顺序

### 第一阶段：一张完整的蜿蜒河谷

保留直河回归图，新图采用作者控制的明显S形河、局部10–18m变宽、内弯沙洲、外弯土坡、宽渔湾与两个错位/斜向跨河口。先让一张图的经济、行军和海陆攻防成立，再扩展热带河湾、湿地、支流与河口。

河岸资源应形成“安全起始资源—近岸扩张资源—争夺资源”的梯度。两岸可以有不同植被和景观，但比较可达资源量、初始资源距离与跨河路程，避免仅按镜像坐标判定公平。桥、港位和近岸资源不能互相堵住。

### 第二阶段：统一地图几何与玩法查询

使用一份地图定义保存曲线中心线、局部河宽、岸坡、桥端点、合法港位和资源点；水面网格、水/陆导航、桥坡高度、小地图、迷雾、鼠标点击、码头朝向与AI路线都从这份数据生成。

预计算水域、岸距、地表高度和船只净空格网，运行时直接查询，避免每个单位反复遍历整条曲线。现有独立水/陆导航层可以继续使用。码头改为随岸线法向朝水，旋转占地、伸水部分、造船出口与模拟阻挡必须一致；AI从合法港位和河道航点选址巡逻。

[AoE3官方随机地图命令](https://support.ageofempires.com/hc/en-us/articles/8478836252564-Random-Map-Scripting-Commands)提供不规则区域、连接、地形平滑与对象距离约束等参考；本项目需按现有模拟与渲染架构实现。

### 第三阶段：改善轮廓和模型，再补水面动态

- 河岸：真正的缓坡、湿土/浅水过渡、沙洲、砾石、成簇芦苇、局部树簇和冲刷凹口。保留行军与建港空地，明确装饰是否阻挡。
- 码头：陆侧仓库＋伸水栈桥/泊位，增加桩基、护舷、系缆柱、踏板和船坞斜坡；仓门做出凹入或打开的轮廓。
- 桥梁：桥台与岸坡接地、承重梁与支撑、自然入口和两种不同轮廓；改动通行宽度后重测大军吞吐。
- 舰艇：船首/尾、龙骨、舵、舷侧厚度、渔夫/舵手与捕鱼/推进动作；转向、受击和开炮有可见反馈。
- 水面：波纹沿曲线流动，浅水颜色、少量岸边泡沫、船尾水迹与轻微摇动。先保持流动为表现，避免同时改变航速规则。
- 资产：缓存可共享网格，补距离LOD和受控材质细节，记录实际绘制、帧时间与内存。

现有最高1.94m的小艇为通过3.2m桥下而设计。经典高桅帆船应放在海岸/河口地图或重新设计通航桥；提高桅杆时要同时确定净空与通行规则。

### 后续内容

热带河湾→湿地与支流→河口/海岸、运输船与登陆→河运贸易和文明专属海军。浅滩要同时处理船吃水与陆水单位相遇，岛屿要连同装卸、登陆点和AI运输一起设计。

## 下一版验收

1. 曲岸、斜桥、窄口下200/400陆军与至少12船双向通行，全员实际到达；逐步检查踩水、船上岸、穿栏杆与瞬移。
2. 多朝向曲岸正常付费建港、连续造船、出口拥堵等待/恢复、取消退款；鱼点有足够船体净空且产生实际收益。
3. 桥上/桥下选择、指定敌人或建筑攻击与换靶、小地图和迷雾位置一致。
4. 六文明轮换正常资源对局，覆盖AI探索岸线、付费建港造船、捕鱼、受袭和海陆攻防。和平经济链与实战分别记录。
5. 固定镜头的全图、河湾、港区、桥梁近景，加原生1倍速的行军、捕鱼和交战视频；编辑器受控截图与原生实玩分别标注。
6. 同机同规模对比模拟Tick、原生帧时间P95/P99/最大值与长时内存，处理集中算路长步。建议普通200陆军+12船场景以原生P95≤33.3ms作为目标，400规模保留压力测试并如实报告，目标尚未达成或验收。
