# 047 / 0.2.23 · AI 施工与持续经济恢复

本轮从当前 0.2.22 正常规则双 AI 长局中找到实际缺口，再修改并运行同配置对照。阶段 D 未完成；用户正在玩的 0.2.21 原生进程保留，未进行桌面操作、退出或替换。以下均是项目 P 策略，未冒称原作官方 AI。

## 发现与改动

旧版 Coast 镜像局虽然能推进到 V / IV 并自然结束，但事件中出现 **33 次**对未完工 Farm / Coin Estate 下达 Gather。AiWorkforce 自己的筛选遗漏 Complete，而 Economy.Gather 对未完工建筑返回，因此工人到场等待。新版统一使用 World.GatherableResource，未完工经济建筑不进入采集候选或可用产率估计，完工后恢复正常采集资格；玩家指令语义、采集率、费用、人口、科技与战斗规则没有改变。

新增 AiConstruction 负责接替中断的施工，每个 AI 决策至多处理一座已有地基。仅处理存活、己方、未完工且地基位置当前可见的建筑；非驻扎工人的队列已经包含该地基的 Build 时不重复派工。候选为未驻扎、未驻守、空闲或只有单条 Gather 的真实工人，不打断已有施工、移动、修理或排队。选择最近候选后向原 ID 发普通 Order / Build，不重新放置地基、不重复付费、不直接增加进度；成功接受后记录 AIConstructionResumed。施工恢复先于普通经济重分配，接替者的 Build 指令会被保留。

安全检查只针对**地基附近已观察到的军事单位**，沿用 max(12, range+4) 范围并排除探险家。不读取雾后敌人。它尚未评估整条实际寻路是否穿过敌军或敌方防御建筑的射程，这仍是后续 AI 路线与避险缺口；不能称为全面安全的施工规划。驻扎村民仍计入总存活劳动力与人口，没有为此增加村民目标。

## 复现和回归

先用真实付费建造复现：农田和钱币庄园会吸引工人离开已可采资源；唯一施工者死亡后没有接替。冻结的 5 项用例在旧代码为 **2 通过 / 3 失败**，实现后同一测试文件哈希未变且 **5/5** 通过。测试继续推进模拟，确认备用资源实际采集入账、原地基在接替后实际完工、只有一次建造付款与一次完工事件。已有施工者和可见袭击的场景作为保护用例。

全量 **EditMode 161/161、PlayMode 163/163** 通过。没有用仅编译成功替代真实规则行为；这些测试也不代替原生人工完整对局。
