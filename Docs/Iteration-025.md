# 0.2.5 输入顺序修复与原生玩家对局

这是开发检查点，不是阶段 C/D 或完整复刻验收。0.2.4 的封存源码、客户端和验证资料保持不变。

## 本轮改动

世界输入统一为到达顺序 FIFO，保留每次左右键、离散快捷键的坐标和修饰键。修复快速框选/右键/编队顺序、同帧多次右键折叠和帧级 Shift 混用。左键选择与右键交互优先级分开；友军不再优先吞掉适用资源或宝藏。小地图与世界指针走同一条输入路径。UI 按钮和 ESC 界面切换会清空待处理世界输入，保留 0.22 秒输入屏障；这段屏障可能吞掉过快的后续操作，明确记录而非称为零延迟。

原始观察、旧实现红灯和测试夹具修正见 Input-Diagnosis-025.md。规则/兵种/经济数值本轮未修改；Implemented-Numbers-025.md 从当前 Rules.json 导出（34 实体定义、37 科技、37 卡牌、25 卡组容量），不是34种兵。

## 仍需处理的原生问题

- Ctrl/Command+1由桌面控制工具发送，但捕获到的Digit1事件save=false。直接KeyboardState的0–9测试通过；真实鼠标保存→数字召回通过。尚未定位是工具注入、Unity平台接收还是其他环节，因此真实物理修饰键组合不标通过。
- 尝试连续点击主城NEXT时，出现Food Convoy 2发送，最后画面是第2页。完整事件确认发送发生，但成因尚未验证；需要真实UGUI分页、动态卡牌启用和连续Modal重建回归。不能用本轮世界输入测试掩盖此疑点。
- 当前TC有10人驻扎仍显示ATK15，源码不按驻扎人数增加火力。Reference-Garrison-025.md区分当前实现、官方墨西哥特定卡牌依据和普通TC尚待交叉核查的规则。
- 本轮原生宝箱领取成功，但没有重新布置与024完全相同的友军覆盖压力情景；该遮挡回归目前是自动化通过，不能称原生同场景复验完成。
- 部分尝试使用旧截图位置框选移动中的村民，只选到箱子或空地；重新框选后能下单。原始截图按尝试保留，不能按文件名推定命令成功。

本局渲染记录mean16.831ms、P9517.519ms、managed6000640字节；包含暂停、面板和少量单位，不是400单位性能验收，也不能代表连续真实高强度操作的帧时间。
