# 036 非模态按钮与连续鼠标指令契约

实施前建立，P项目交互规则。未声称是原作内部输入实现。

本轮先使用封存0.2.14正常玩家镜像局尝试主动攻城，对局ID92a583564e4340a987c0d5cc3d655b5f。原生记录三次focus_lost、两次成功manual_resume；最后95.399秒暂停后正常退出，winner=-1，尚未完成建房、时代II或攻城。若干F9尝试未生成文件。该局是中断的检查，不能作为正常完整实战通过证据。

三个候选原因分别是应用没有重新获得系统焦点、设备复位后的状态仍阻挡新输入、按钮转换屏蔽时间吞掉新点击。前两项需要原生焦点/设备证据，尚未归因。源码显示所有UGUI按钮回调均无条件调用SuppressWorldInput(false)，使普通造兵、取消、攻击移动等按钮也开启0.22秒地面指针屏蔽。接下来单独验证第三项，不能因其测试成立而宣称系统焦点或F9问题已解决。

## 期望交互

- 在已经显示的普通HUD按钮完成一次按下/抬起后，新一次完整地面点击应按FIFO立即处理，不需要等待220ms。覆盖训练后选择工人并按B、取消训练后设置资源集结、攻击移动按钮后指定目的地。
- 两次点击必须具有各自的down/up，不能将UI点击的同一次抬起当成世界点击。按钮按下后拖出UI抬起，不得触发按钮、地面选择或命令。
- 真实UGUI按钮仍由UiPointerDispatcher拥有其手势，世界命令和键盘继续共用DiscreteInputBuffer。重新生成按钮时继续等待实际Canvas布局，不复用旧按钮。
- 模态关闭、建造放置入口、暂停恢复、失焦和重开沿用既有隔离策略；本轮不删掉这些入口的保护，不改变失焦自动暂停，也不允许读取后台输入直接控制游戏。
- 经济扣费、退款、人口、攻击间隔、AI和数据数值均保持原规则。只修正普通HUD按钮对后续独立鼠标动作的影响。

## 证明与边界

先以同一组真实InputSystem/UGUI场景测试在旧运行时建立失败信号，再修改运行时。测试必须检查真实选择、命令、付款/退款和队列，不能只检查私有字段或调用Button.onClick.Invoke。同批输入和快速后续输入要有明确事件顺序，不能等待越过220ms而产生假通过。

修复后运行相关输入回归和全量EditMode/PlayMode，再实际构建并检查客户端按钮到世界操作。原生窗口继续失焦或无法恢复时，记录未验收边界，不能用场景测试关闭该问题。用户主动攻城仍为后续核心验收项。
