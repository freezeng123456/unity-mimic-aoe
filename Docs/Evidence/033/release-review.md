# 033 artillery release review

Read-only review of the current `MovementCombat.Fire` minimum-range guard, `AttackReleaseTests`, `TargetReleaseVisibilityTests`, and recorded test results. No Unity launch or source mutation performed.

The current change computes the normal/melee range, then checks `EdgeDistance` at fire time. If the target has crossed inside `e.def.minRange`, it emits one `AttackCancelled` event and returns; otherwise it retains the existing upper-range check, damage-kind selection, siege conversion, projectile creation, and `Fire` event (`MovementCombat.cs:230–247`). The cancellation occurs after `TryAttack` has already set `attackReadyAt` and `fireAt`, so it does not refund or extend the reload deadline. The next eligible attack can occur only when that original cooldown expires.

1. **No装填绕过 or mode-branch error is evident.** The guard is inside `Fire`, after the existing target/visibility/firepower checks and before damage/projectile creation. It applies to both melee and ranged paths through the selected `range`; a Field Cannon has `meleeDamage=0`, so `forceMelee` cannot make it melee. A cancelled shot emits no `Fire`, creates no projectile, and leaves `attackReadyAt` unchanged. This is directly asserted by `AttackReleaseTests.TargetEnteringMinimumRangeCancelsPreparationAndPreservesDeadline` and `TargetDeathBeforeFireCancelsShotWithoutResettingDeadline`.
2. **The tests cover the intended release cases without asserting a false projectile result.** `AttackReleaseTests` uses the shipped cannon definition (cloned catalog, no shared mutation), fixed `MatchSimulation.StepSeconds`, checks inclusive exact minimum range, verifies an already-fired projectile still impacts after the target enters the dead angle, and verifies target disappearance before fire does not reset cooldown. `TargetReleaseVisibilityTests` verifies visibility loss and real garrisoning before fire cancel the shot, with no projectile and unchanged deadline. These tests support the narrow cancellation contract and event behavior.
3. **Coverage and claims remain bounded.** Recorded artifacts show EditMode `110/110` passed (`work/verification/033/EditMode-final.xml`) and PlayMode `115/115` passed (`work/verification/033/PlayMode.xml`). This establishes the checked test assemblies for that run. It does not prove a full normal match, every artillery unit, every movement topology, or that native focus/input/AI target choice is universally correct. The current release tests are simulation-level; they do not cover screen picking or a live human attack order.

The only notable event detail is intentional: a minimum-range cancellation emits `AttackCancelled` but not `Fire`; the already-spent cooldown remains. `TargetEnteringMinimumRangeCancelsPreparationAndPreservesDeadline` directly asserts zero `Fire` and an unchanged deadline; the no-projectile consequence follows from the static early return, while `TargetDeathBeforeFireCancelsShotWithoutResettingDeadline` directly asserts no projectile for its death case. The tests do not directly assert an `AttackCancelled` count for the dead-angle case. No duplicate event path is visible in the reviewed code: `Fire` is emitted once only after projectile/direct damage setup, while the new cancellation branch emits once and returns.
