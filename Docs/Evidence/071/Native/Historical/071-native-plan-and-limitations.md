## 操作顺序

1. **预览、付款与退款。** 选城镇 → REVOLUTION，记录成本、90s 与符合条件的工人数；KEEP PLAYING 后资源和队列不变。再次预览 → START REVOLUTION，核真实 Revolution command 和一次付款；点击生产队列取消，核原付款全额退款、仍为 Empire、工人入口恢复。
2. **实际完成与母城刷新。** 再次正常付款；提前选定一个工人并保存控制组，保持 HOME CITY 打开至普通调度完成。核完成事件、相同实体 ID/人口、单位转为革命兵、母城展示革命卡组及“供应箱可继续在途”文案。关母城检查原工具消失、步枪可见、选中 ID 与组仍有效。此截图证明观察帧的状态；严格同帧边界由自动化专用测试证明。
3. **冷恢复与重建。** 革命未完成时通过 SAVE MATCH 保存槽位，正常 QUIT；新进程 LOAD SAVED MATCH，比较保存时的队列 elapsed/paid、phase、单位 ID 与原槽 SHA，RESUME 后完成。再通过 CIVILIAN GOVERNMENT → REBUILD CIVILIAN GOVERNMENT 正常付费；重建中重复保存、退出、新进程恢复。完成后核旧革命兵不还原、可正常支付训练首个工人、时代 V 仍不可升。记录每段进程与录像身份。
4. **补给动作和人口恢复。** 实际右键自有箱，核 Gather 指定目标、箱 remaining 减少和资源实际到账；采集未耗尽时核步枪隐藏，真实 STOP 后恢复。右键天然树应为普通 Move，树与木材不产生采集收益。选一名革命兵，DISBAND → KEEP UNITS 验证未变；再确认 DISBAND 1 UNITS，核精确 actor 被移除、人口减少 1、无资源/经验收益、其它己方及外方仍活；召回该空组无异常。
5. **录像库与重演。** 保存本次真实输入录像，正常返回菜单；分别记录一次冷首开和同进程 REFRESH 的开始/显示完成时间、文件数量和总字节数。选择录像完整打开，FROM START 后只向前播放至 RECORDED SEGMENT VERIFIED，核革命/重建/遣散事件与最终状态，禁止用跳到末尾代替顺序重演。若包含多个冷恢复片段，逐片段记录起始边界与完成状态。
6. **最终目标显示。** 使用短 authored 目标，通过普通时间触发完成或截止失败；结果框出现时记录背景目标摘要，须显示 COMPLETED/FAILED。保持时间停在同一显示秒内；不重复 070 三章的完整通关流程。
7. **异常反馈与正常退出。** 在仅用于此次验收的录像副本上检查坏文件和错误 build 显示不可打开，副本保持原字节，合法录像仍可完整打开。最终通过菜单 QUIT，核退出 0、日志异常及关闭警告；有 Mono/内存警告就如实列出，不宣称零泄漏。

## 文档应明确的局限

- 原生鼠标、渲染与新进程恢复在执行上述步骤前仍未验收；自动化 InputSystem fixture 不等同实际原生窗口。未完成的步骤保留 pending，失败如实记为失败及其重试身份。
- Catalog 的缓存只在当前进程内保存已完全验证的少量元数据，上限 256 个内容/身份条目。首次冷读、缓存淘汰或新 bytes/规则/build 会重新完整验证；暖刷新仍读文件、计算实际 SHA 和进行 UTF-8 解码。小 fixture 的耗时不能推广到六个真实大录像或所有机器。
- 完整 Read/Open/ReplaySession 验证保持原合同。目录里的“RECORDED SEGMENT”表示内容可打开，不等于已经顺序播放成功；“INTERRUPTED”也不能宣称完整比赛。
- 录像只支持其确切 app/build/Unity/规则/地图与目录版本身份。070 冻结证据及原录像保留在原候选目录；此版本不能据目录存在就声称可打开旧 build 的录像。
