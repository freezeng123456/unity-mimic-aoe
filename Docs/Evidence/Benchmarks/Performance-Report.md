# 原生客户端性能短样本 · 0.1.2

本机 Apple M4 Pro（14 CPU 核/20 GPU 核）、48 GB RAM、macOS 26.5，Unity 6000.6.0f1 / URP 17.6.0，macOS arm64 Development/Mono。通过 macOS 应用入口启动真实客户端，Metal，2560×1440，60 FPS 上限，vSync 关闭。每档独立运行 25 秒，前 5 秒预热，统计其后约 20 秒。

夹具生成两方混合步兵、骑兵和炮兵，执行攻击移动；把夹具单位运行时 HP 提高至 1000000 来保持活动数量。此修改仅在显式 `-frontierBenchmark` 参数下启用，正常菜单、正常 AI 与自动完整对局均不使用。夹具的实际单位数与正常人口制度不同，不能把 HUD 人口当作活动实体计数。

这些 CPU 项是本项目 Stopwatch 埋点：导航项包含局部移动，战斗项为该模拟区段扣除移动时间，经济项包含工作/生产/船运。末次 tick 采样在渲染帧中读取，不是 Unity Profiler 的独立 GPU/子系统全量测量，不能将各列相加当作总帧时间。Unity 分配量不是进程 RSS；托管净增长包含事件记录和仍存活状态，不等于累计分配量。Mono 各代计数可能同时增加，不能把三列相加称为总收集次数。

400 单位平均约 16.93 ms，但 P99 约 32.91 ms，存在尖峰。短样本不证明长期无卡顿、4K60、完整地图战斗性能或窄口通行质量。场景保持完整渲染，部分单位会被 HUD/地形遮挡；此数据不是“所有单位无遮挡可操作”的验收。

200 单位的最初一次运行与另一个已暂停但仍渲染的客户端重叠，已剔除，重新用单独实例采样。最终 JSON 来自独立运行。原始文件：同目录四个 `units-*.json`；报告保留实际 appVersion、分辨率、机型、活动数量和预热时间。
