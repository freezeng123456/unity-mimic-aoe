# 输入投影与单位拾取的只读核对

针对 0.2.31 原生窗口中“点大炮选到附近骑兵”和“移动偏左”的观察，仅检查冻结源码、既有测试结果及本机 Player.log；未操作 GUI、运行 Unity、修改源码或读取对局敌军状态。源码 SHA 与只读结果见 [read-only-audit.json](read-only-audit.json)。

**未确认固定横向坐标偏移。** 鼠标事件位置直接交给同一相机的 `ScreenPointToRay`，地面位置以 Y=0 平面计算；未见表现源码另加 Retina 缩放或横向补偿。日志确认渲染窗口曾从 2560×1440 切到 3456×1924，途中出现 3456×2168，随后回到 3456×1924。但 `FRONTIER_INPUT`、`FRONTIER_SELECTION`、`FRONTIER_UI`、`FRONTIER_FOCUS` trace 均为 0 条，无法还原那次点击的按下/松开位置、选择对象和当时镜头。不能据此证明外部鼠标工具的桌面坐标转换正确，也不能把操作观察推导为 Unity 固定偏移故障。

| 源码位置 | 已确认机制 |
| --- | --- |
| `DiscreteInputBuffer.cs:105–118`；`RtsInput.cs:254` | 事件保存自身鼠标位置，地面点击由相机射线求交；不使用 HUD 的 1600×900 布局坐标替代世界坐标。 |
| `RtsInput.cs:265–284`；`ProceduralArt.cs:22,157–170` | 单位只按模拟位置 + Y=1 的投影中心圆拾取，选最近中心，不射线命中整套模型；primitive Collider 会被删除。大炮炮口可在圆外，附近骑兵中心可以胜出。这是完整外形点击覆盖的具体 UX 边界。 |
| `World.cs:123,133–139`；`GridNavigation.cs:136–143` | 多人移动分配阵型槽位，并非所有单位落在点击点。含大炮的编组间距至少 3.3 米；无遮挡两人组的第二槽位在目标左下各 3.3 米。地图边缘、不可行走地形还会改变合法槽位。 |
| `RtsInput.cs:250`；`MovementDestinations.cs:23–53` | 右键命中附近友军等对象时，即使最后是 Move，也使用该对象位置；空地才保留地面点。被占据端点可转到附近可达空位，并产生 `DestinationAdjusted`。 |
| `RtsInput.cs:43,68,131–136,164`；`CameraPanInput.cs:12` | F、数字编组召回会移动镜头；屏幕边沿会自动平移。镜头变化后，旧截图像素不能继续指代同一地面点。 |
| `WorldView.cs:139–140,203` | 显示位置有插值，拾取使用模拟位置，移动中可能短暂不完全重合；暂停会保留当帧残余差异。Y=1 高度本身只产生竖向投影差，不能解释固定横向左移。 |

在 3456×1924、zoom=26 下，静态参数推导的单位点击半径为 25.9 像素（横向约 0.7 米）；朝右炮口距拾取中心可约 48.3 像素，含大炮两人组的第二单位阵型偏移约左 122.1／下 93.5 像素，边沿平移带宽约 57.7 像素。**这些数值是源码推导，未复现或判定当前对局的具体点击。**

合法操作建议：点炮车车架／两轮中间，或框选后确认 HUD 的 Cannon 与选择数量；保存独立炮兵编组。数字召回或 F 后重新看画面，再点无单位、资源或建筑的空地；观察黄色回执圆与最终阵型的区别。必要时用 M 循环自有军队，避免模型重叠时反复点炮口。恢复暂停后留出约 0.25 秒的鼠标输入屏障。

既有 055 全量绿测试包含投影中心选炮与炮兵右键攻城、FIFO 点击坐标、建筑屋顶／资源外形拾取和镜头控制。它们不覆盖炮口与骑兵重叠时的完整单位外形拾取，也不证明当前 3456×1924 窗口的外部 GUI 坐标转换。该 UX 边界不新增 A–D 里程碑退出条件，不扩大发布修改范围；0.2.32 仍只允许既定 HUD 两段 literal 与项目版本号的两文件变化。
