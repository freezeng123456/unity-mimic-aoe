# 052 / 0.2.28 · 驻守选敌与连续攻击指令

继续小步修复实际交战操作。驻守炮兵不再被最小射程内的近敌锁住；驻守火枪兵原目标移出射程但仍可见时，也能重新选择当前可射击的目标。连续右键确认同一个直接攻击目标保留正在进行的抬枪/射击准备，避免重复取消而一直不开火。实时阴影保持关闭。

## 复现与修复范围

四项正常兵种参数的受控测试在旧0.2.27全部失败：炮兵有死角近敌和可射击远敌时6秒无远敌Fire；炮兵已记住的目标实际走进死角后无远敌Fire；驻守火枪兵旧目标移出射程但仍可见后无新目标Fire；每0.1模拟秒重复同一个直接Attack，8秒内Fire为0。没有改攻击力、射程、最小射程、准备时间或冷却数值。

首轮火枪兵夹具让敌人完成移动后自动反向追击，断言时它已经回到射程内；这是假设布置错误。改为目标完成真实Move后立即下达真实Hold，再冻结文件、重跑四个产品失败。初始错误记录和最终红例都保留，不把夹具问题算成产品缺陷。

另五项旧版对照通过：只移除死角干扰单位后炮兵会正常射击；停止密集重发Attack后火枪兵会正常射击；实际AttackMove击杀连续遇到的两个敌人后仍能执行后续地面移动；显式Attack可追击射程外目标；更换直接目标取消原准备但不退还冷却。目标死亡续行假设没有复现为新缺陷，因此保留旧行为。

生产修改限于MovementCombat.cs和World.cs。首次自动选敌与记忆目标现在共用驻守/建筑的可射击范围检查。自由行动单位仍可追击，显式Attack仍优先跟随玩家目标；Fire时仍检查目标存活、可见性、驻扎状态和射程。准备、发射、在途弹丸及命中时序未改。

相同非追加直接Attack仅当当前队首和正在交战目标均与新目标相同时保留fireAt/attackTarget；替换会清除旧的Shift后续队列。真正改目标、移动、停止或驻守仍取消准备，attackReadyAt保持。Shift追加订单保留当前准备。这是本项目P指令政策，未声称是已核实的商业参考游戏精确规则。
