# 0.2.13 · 输入复位与按住状态 034

本轮修复设备复位、按住状态和 UI 捕获之间的输入边界。复位按设备清理旧边沿并保持键盘/鼠标隔离；跨焦点恢复时，已知仍按住的键或按钮不会被重新解释为新的操作，释放后 fresh press 才能触发。恢复后的非 held 首个真实事件继续进入输入路径，避免无条件吞掉有效 F9 等操作。普通 UI 清理只取消待分发边沿和捕获，不把物理按住改写成新按下。

冻结 reset/focus 测试从旧运行时 `7/10` 通过提升到最终 `10/10`，隔离用例为 `4/4`；最终全量 EditMode 为 `110/110`，PlayMode 为 `129/129`。最终构建为 0.2.13，Build GUID `ae1dace836c84d79b94d291667478592`，Unity 6000.6.0f1（正式非 LTS），macOS arm64 Development/Mono。构建回执记录 125 项输入、两份运行时脚本与版本设置的三项变更，诊断探针已移除；这些结果证明固定测试与构建输入/产物一致，不能扩展为确定性回放或联网能力。

最终 CLI 原生样本在 `65.399570` 模拟秒失焦暂停，Finder 样本在 `20.100040` 模拟秒失焦暂停；两次都没有成功完成恢复窗口后的操作链，不能据此声称 macOS OS focus 已修好。正常 Finder 启动曾完成菜单、开局、采集和支付 `100 F`，最小化时训练队列剩余约 `19 s`。随后经应用入口开启的正常玩家镜像局在 `803.750793` 秒自然败北，记录三次失焦后主动恢复；另外两次失败仍是有效限制。

旧 0.2.12 临时诊断探针使用独立 GUID `276339a26de042219d74a2604d163dfd`，仅作为诊断记录，不能替代最终 0.2.13 客户端。新正常局已联动采集、建造、时代 II、两次船运、驻扎、修理、AI围攻、自然结算、重开与返回菜单；玩家没有进入 III，训练中的军营被毁，未产出炮兵，完整主动攻城仍未验收。精确事件与操作限制见 [Native-Verification-034.md](Native-Verification-034.md)。
