# 051 / 0.2.27 · 动态目的地与友军绕行

本轮继续修复影响实际行军的小范围问题，实时阴影保持关闭。新建筑或施工村民占住原先指定的目的地后，单位会保留原始意图，并选择附近可达空位；抵达后继续后续Shift指令。炮兵被已到位友军围住时，卡住恢复会计算绕开附近静止友军的路线。未修改经济数值、单位速度、伤害、AI决策、素材或依赖。

## 已复现的问题

旧0.2.26的FindPath把建筑中的终点移到了附近可行位置，上层抵达判断却继续比较建筑里的旧坐标。单个Move、AttackMove和带后续Shift指令均复现：单位到达(52,58)后仍等待进入(52,60)，45/90模拟秒后订单未完成。

50混合单位先获得不同目的地，再由实际付费施工落下两座房屋。两个原目的地被地基覆盖，另两个被施工村民的站位影响，最终4单位订单未完成。只命令两个施工村民离开，受村民影响的两个指定单位能完成，被地基覆盖的两个仍未完成。该控制中还出现一个受停滞同伴影响的新堵塞，因此没有把控制结果夸大成只剩两单位或全部群体问题已解释。

四个正式回归用例在旧运行时全部失败，测试文件随后冻结。最初混编夹具的落点与贸易站点重叠，先改到合法地面再冻结并重跑；这一夹具错误不是产品缺陷。

## 本项目导航政策（P）

这部分是本项目主动实现的导航政策，不声称是商业参考游戏的算法或已经核实的原作数值：

- UnitOrder.point保留玩家或AI的原始指令；resolvedPoint仅保存实际局部替代终点。只有终点被地形或静止友军占用才寻找替代点，途中被整道墙挡住不会直接算抵达。
- 候选点限于原始点8世界单位内的半单位网格，遵守单位半径和建筑障碍，并与友军当前移动目的地及静止位置留出空间。按距原意图优先排序，需要真实路线。每次最多12次路线查询；无解每1.2模拟秒继续候选，不删除原订单。替代点稳定可用时沿用；导航版本变化后重新检查，取消/摧毁建筑可使未完成订单回到原意图。
- 替代终点变化记录DestinationAdjusted事件，含原目标说明、实际终点和距离。既有费用、人口、开火和战斗冷却结算不由这条事件触发。
- 最初终点修复解决了3个单体/队列用例，但混编另有炮兵的普通终点一直可用，实际卡在已经站定的友军之间。轨迹证明该炮全程没有解析替代终点；候选数量不足的猜测被排除。只增加局部绕行方向的两版尝试仍失败并影响400单位检查，已撤回。
- 最终恢复只在原有约2模拟秒的沿路进展计时触发时，快照附近16单位范围的静止己方单位圆盘，为本次A*增加临时可走判定。节点、连接和平滑路径都使用该约束；不修改共享地形网格或导航Version。已接触的起点允许向外脱离，不瞬移或加深接触。找到路线后，快捷跳点也检查当时的静止友军，避免重新抄近路穿回堵点；失败则保留原有局部绕行机制。
- 正常指令与AI共用上述路径。敌军隐藏坐标和敌军目标订单没有加入这两个新功能。目的地解析开销计入LastNavigationMs；本轮没有据此声称客户端帧率达标。

## 验证与限度

冻结的4个旧红例现全部通过。同一50混编夹具中，50单位都完成订单、最终位置互不重叠，距各自原意图小于5；每模拟步检查不进入地形障碍。建筑付费取消和敌方伤害摧毁两例验证导航版本更新、原意图保持、恢复原终点和位移不超过速度上限。

既有开放地面50、动态整墙移除、100/200/400混合单位通过唯一通道、100同阵营混合单位相向通行一并通过。以上是模拟实体数量与通行断言；不是人口数，不是50/100/200/400独立客户端性能矩阵，也不覆盖所有桥梁、包围、交战和短暂单位重叠的组合。

新增PlayMode通过真实InputSystem鼠标右键、持续按住Shift再右键、释放Shift，调用生产输入控制器生成两个订单，再实际付费施工覆盖第一个终点。测试逐步推进World并验证先靠近第一目标、再执行第二目标、订单原点保持、每步地形可行和不瞬移。它是Unity输入集成测试；模拟由夹具推进，不是人工操作独立客户端。

全量 **EditMode173/173、PlayMode177/177** 通过，没有通过放宽原四例或既有通道断言来消除失败。
