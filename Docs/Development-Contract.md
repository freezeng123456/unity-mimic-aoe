# 烽岸纪元 Frontier Reckoning — 开发合同与规则账本

建立日期：2026-09-14。独立原创 Unity 陆战 RTS；不是官方游戏，也不宣称完成复刻。

## 证据级别
- R：官方资料已支持的参考机制，须链接到 Reference 文档中对应条目。
- P：本项目主动选择/简化，包括所有尚无精确原始数据支持的数值。
- U：待核实的原作细节；不能作为原作结论。
- I：代码已实现；T：规则/场景自动验证；V：独立客户端实际检查。I/T 不能替代 V。

先完成本账本、初始数值与实现清单，再开始游戏开发；研究补充在 Reference-Economy.md 与 Reference-Combat-Shipments.md。精确原作版本尚未冻结，不能混称最新 DE 平衡数据。当前实施目标采用独立 P 数值。

A：独立 Unity/URP 工程、镜头、选择、命令、建造、人口、生产、采集、基础战斗和群体导航；至少一次原生运行检查。
B：先一个文明的镜像 1V1，I-III，合法卡组/XP/真实船运、可见性、AI、主菜单到结算；必须完成原生客户端整局，保留日志和实测边界。
C：B 验证后，第二文明及 I-V、科技/特色单位/银行差异、贸易与宝藏、完整攻城和 AI；全部验收才称完整陆战。
D：正式美术/动画/音频与更广规模验证，随后再讨论海战/联网/编辑器。

## 初始实施规则（全部 P，待研究追踪）
P01：10 Hz 固定模拟步长，表现按渲染帧更新；不宣称跨平台确定性。暂停不推进模拟时间。
P02：采集在工作点连续入账，资源有限；不实现携带/回城。每笔经济变化记录原因和实体，禁止无来源赠送。开局配置单独记录。
P03：建筑占地立即阻挡导航；施工取消返还 75% 原始费用，排队训练/研究取消返还 100% 未完成订单费用；完成后不可退款。多工人施工速度按 1 + 0.5*(人数-1)，最多 8 人。以上退款/施工公式不是原作核实值。
P04：训练入队预留人口；住房摧毁导致超上限保留已有单位，禁止新增预留；已预留订单完成仍可出生。船运单位在到达时检查当前已用+预留+本次人数，空间或人口不足等待；不丢失船运。建筑被毁，队列损失不退款（P）。
P05：科技通过玩家已完成科技集合派生最终属性，不修改共享基础定义、不重复叠加；已有和新产出单位读取相同属性。满生命比例随最大生命变化保持。先不提供保存/载入，明确缺项。
P06：XP 仅来自列明的采集/建造/生产/击杀事件；机会门槛初始 150，每次后续 +75。卡牌到达串行 35 秒，送出立即消耗机会；一次性卡在发出时锁定；有限项目卡组容量 8，预置经济/军备卡组；这是项目规模选择，不宣称原作限制。
P07：伤害=基础伤害*对适用标签的最大一项倍率*(1-对应抗性)，不累乘多标签倍率（P）。攻击准备后发射，冷却锚定模拟时间，换指令不重置；弹丸飞行后按实体目标结算，目标死/驻扎即丢弃。发射后可命中进入迷雾的目标，不能产生额外敌情；无友伤。
P08：单位使用网格 A*、动态建筑阻挡、分散目的地与局部避让；不允许同点堆叠当编队。包围、桥口与堵塞必须实测，未通过列问题。
P09：三态迷雾所有查询同源；AI 只获得自己的状态、可见敌人和最后观测位置；地形知识可共享，敌实时单位不可共享。AI 不免费造兵或加资源。
P10：消灭判定为敌方全部存活单位与建筑被清除，另有认输；第一座城镇中心被毁不触发直接获胜。接收点丢失的船运等待其他合规建筑；不能阻止消灭判定。
P11：地图 128x128 世界单位，格宽 1，常规人形半径 0.4，骑兵 0.65，建筑长宽在数据中定义。固定种子 314159，先对称陆图；地图尺寸/种子在记录中写出。
P12：首文明“海岸盟约”以住房完成产出村民为结构机制；后文明“河谷商邦”以钱币训练村民与银行产币为结构机制。对应英/荷参考研究，仅名称与资产原创；不同于原作处逐条保留。

## 当前规则对初始账本的补充

P06 中的 8 张是初始开发规模。当前冻结 0.2.31 的 `Assets/Resources/Rules.json` 将卡组上限设为 **25**；`DeckLibrary.Validate` 接受 1–25 张不重复、适用于所选文明的卡牌，经济/军备预设各选 25 张。XP 门槛与串行 35 秒运输仍按上述项目规则执行。此说明反映已有实现，不修改 A–D 的退出条件；它也不表示原作规则已经核实。

## 数据权威与模块边界
规则配置 Catalog -> 只读定义；PlayerState/EntityState -> 可变状态；GameCommand -> 玩家与 AI 的唯一操作入口；World -> 固定步长、经济/战斗/队列；Navigation/Fog -> 空间与信息；Unity GameObjects/UI/Audio -> 只反映状态与事件。渲染与动画不扣血、不发资源。
编辑器生成并保存真实 Unity 场景/URP 资产；构建入口为场景，不能以网页包装替代。测试项目不导入任何商业游戏资产。

## 验证约定
每项报告写清通过/失败/受阻/未检验。自动模拟对局、鼠标键盘可操作实测、人工完整对局与性能压力样本分别报告。自动运行完结不证明完整操作体验。人口不等于活动实体数。客户端只能交付构建成功的实际平台。

## 0.1.2 实测后的规则补充（P）

- 默认混合编队中心间距为 `max(1.8, 最大半径×4+0.3)`，让最大单位可从已停下友军之间穿过。此版本采用较疏的队形，未实现紧密/松散队形切换，不能称为原作编队算法。局部方向采样和超过 2 秒没有缩短目标距离时的绕行用于恢复；50 混合单位实移与动态墙解除已通过自动测试。桥梁、双向窄口、400 单位同时通过狭口仍需专项验证。
- 时代完成后的奖励保存在玩家待接收队列；出口受阻或接收建筑丢失时不丢失奖励。奖励箱仍需采集。
- 范围伤害对每个敌方目标单独计算对应标签与抗性，副目标为基础倍率的 50%；无友伤。
- 攻击准备可被新指令取消，既定冷却仍继续；已发射弹丸不因后续指令取消。
- 同一帧内多个鼠标边沿和数字键修饰组合按原始输入事件保存，防止快速拖动/双击/编队键的起点或修饰键丢失。
