## 按实际结果推进

1. **先关闭当前073观察。** 三条预声明普通I/standard/双AI为winding Ottoman44/45和river_bend Dutch42，2400cap、1500比较点、30秒采样，无运行注资/强制命令/干预。核实际exit、前后源身份、自然终局/cap、付款/市场收入/设施完成/运输和军事行为；Step、采样/事件写盘、最终保存计时分开。三case不扩成16局全部路线、文明平衡或原生FPS。
2. **再完成当前GUID原生与私有交付。** 用真实市场100/500交易、陈旧报价/权限/按住刷新与当前版保存/冷恢复/录像验证声明范围，保留未完成项。冻结源码/客户端/证据/画廊后独立核成员/CRC/字节SHA，再上传原私有范围并读回实际远端字节与owner-only；最终Git提交/推送另核。072原件和包保持不变。
3. **沿证实缺口补路线和经济线防御。** 普通Gather实际导航仍可能穿过威胁区，市场不解决逐帧安全或动态护送。后续须将合法路径检查与执行衔接，观察资源区扩张、敌袭撤回、工人/地基存活和实际收入；没有资源/工人/安全路时保持自然失败。
4. **用分项测量决定性能优化，再扩内容。** 072Dutch总wall包含I/O，末段Muster是调度证据而非主CPU归因。先读新实际Step/写盘分项，必要时从原精确World/Controller做独立有界profile；同输入候选须核最终World/Controller/事件一致，当前原生性能另验。保持合同后继续国别卡组、舰队/港区争夺和用途明确的视听改进。
