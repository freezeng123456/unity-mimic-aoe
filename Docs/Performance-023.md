# 0.2.3 本机短时压力记录

机器：Apple M4 Pro，48 GiB内存，macOS26.5；客户端Unity6000.6.0f1、macOS arm64 Development / Mono、Metal、2560×1440、60fps上限、vSync关闭。每档独立启动并退出客户端，没有并行其他Unity客户端。每次25秒、前5秒预热、随后约20秒采样。桌面锁屏，无法验证可见窗口、动画读图或输入；这些是原始短时压力诊断，不是性能验收，也不支持4K60或长局无卡顿结论。

夹具提升单位运行时生命，维持50/100/200/400个活动军事实体；这是明确启用的测试模式，不是普通对局AI加成。包含长枪/火枪/骑兵/炮兵与交替群体攻击移动。人口值、屏幕内可见数量和累计创建实体数量不等于这里的活动单位数。

计时限制：navigationPerTickSampleMs/combatPerTickSampleMs/economyPerTickSampleMs字段是在渲染帧上读取“最近一次模拟步”的耗时，再求平均，同一次步可能重复读到，不能当作严格每步分布或CPU占比；simulationPerRenderedFrameMs是客户端记录的每渲染帧模拟耗时。原始JSON保留字段名与值，不伪造更精确的测量。GC0/1/2为运行时计数差值，不相加宣称为三个独立世代的回收总次数。

200单位的P99高于400单位，单个20秒样本不能解释这一反常或证明400单位表现更好。本轮未看到随实体数增加的持续帧时间上升，但每档均有GC且未记录分配栈，仍需在解锁的可见窗口下测量长时对局、拥挤通道、动态建筑、大规模集结及玩家输入延迟。新动作每帧恢复和解算刚性关节；是否需要缓存/调度应依据这些后续剖析结果，不凭此样本改用ECS/Jobs。
