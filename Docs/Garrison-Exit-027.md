# 0.2.7 释放与自动集结补充契约

本轮第一候选的原生测试中，六名村民进入城镇中心后释放，在约一分钟后仍有单位保持Moving。输入修复通过不代表移动生命周期已通过。因此第一候选保留为诊断包，最终交付必须修复并复测此问题。

修复前的五项EditMode回归全部失败：六人释放后45秒仍有Move订单、两个连续训练批次无法全部停稳、建筑被毁十人同坐标重叠、受阻首选出口重叠，以及全出口阻塞仍强行释放。这些均通过真实World命令和Tick复现。

本项目对主动释放采用已用于生产/船运的空闲出生位置检查，按最大单位半径为整组选择不重叠、可行走出口。整组空间不足则保留原驻扎关系和人口，不扣资源，不强制挤出；玩家清除阻塞后可重试。释放后与训练完成的单位共用自动集结分配，使用网格队形候选，避开外部单位当前位置及已下达的移动终点，每名单位拥有独立终点。没有可用终点的单位留在安全出口并显示等待状态，不能无限挤向一个点。

建筑被毁后不再把全员放在同一边缘坐标。优先使用安全外侧位置，不足时使用建筑原占地及周边可行走的空位；临时连空位也没有的剩余驻扎者保留为待疏散，每秒重试，不凭空消灭或重生。人口不因释放而重新增加。此项是本项目生命周期设计，未声称是参考游戏原始规则。暂时待疏散与首次出生不同，不重新收取训练费用或重复奖励。

本轮不改变玩家Move/AttackMove的现有导航算法、地图尺度、采集与生产时间、兵种或文明数值。新增RallyAssigned/Ungarrison事件让实际位置分配和释放可追溯。自动集结行为改变后应重新运行全量规则/生命周期测试、原生释放操作及普通自动对局；旧版本的对局事件序列不能当作新版确定性证明。
