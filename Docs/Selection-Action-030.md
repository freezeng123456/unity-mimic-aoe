# 选择变化与按钮输入顺序 · 030

2026-09-14，目标版本 0.2.10。契约在修改运行时代码前冻结；现已实现并完成自动回归，独立客户端已完成有明确边界的快速选择/训练与重开复查，详见Native-Verification-030.md。

## 证据与范围

0.2.9 正常玩家整局 NativePlayer.log 的输入时间 86.7372 接收 T，86.7642 接收左键按下，相差 27 ms；随后旧 ATTACK MOVE 按钮执行，世界时间 54.200 秒。配套截图显示已选城镇中心仍处于攻击移动模式。已有构建、封存源码包保持不变。

这是本项目原生输入/UI 的 P 类行为契约，不新增或宣称核实任何 AoE3 原作规则。模拟经济、战斗、AI、卡牌与数值不在本次修改范围内。

## 必须满足的顺序

1. 选择快捷键发生在鼠标按下之前：先应用新的选择及按钮布局，再处理仍留在 FIFO 中的点击。同坐标此时指向当前按钮；T 后首槽训练村民，V 后首槽为攻击移动。不能把新点击全部吞掉。
2. 旧选择的按钮已按下，再切换选择，再抬起：取消旧上下文的按压，不调用旧回调，也不将抬起重新解释为新按钮点击。
3. 同一选择的按下/抬起仍能执行一次，不能因周期性资源或队列刷新重复扣款或丢失点击。
4. 按钮第一次布局需要一帧时只保留尚未处理的输入，不能依据鼠标最终保持按下而永久等待布局。
5. 与 028 模态窗口隔离、ESC 指针屏障以及 029 资源集结点语义兼容；选择变化本身不修改模拟状态。
