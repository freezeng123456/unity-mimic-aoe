# 0.2.4 原生人工输入检查与未修复问题

状态：真实Mac客户端操作已执行，以下缺陷未在0.2.4修复；下一版本优先处理。不是美术离屏图推断。证据在交付旁Verification-0.2.4的native-manual-*.jpeg、native-manual-mirror.json/JSONL、NativeManual.log。先保留当前完整源码/客户端基线，再改变输入代码。

## 快速框选与右键顺序

从0.2.4实际窗口连续发送左键框选和右键时，随后仍显示城镇中心并出现通用Accepted，村民保持闲置；单独框选后已显示5 SELECTED，再右键则Gather成功。代码核查：RtsInput.Update的rightButton.wasPressedThisFrame在pointerEdges消费前，右键使用旧Selected，而左键事件在后面才更新选择。还必须验证两个右键都在一渲染帧内时各自位置是否保留，以及框选后同帧编队保存。

修复应按实际事件次序执行选择、右键和离散快捷键，保存每条事件的坐标与修饰键。不能简单把一帧全部左键移动到全部右键之前，否则右键→后选另单位的反向顺序仍错。保留UI隔离、建造取消、攻击移动、Shift队列与暂停规则。

## 友军遮挡宝箱

探险家右键宝箱，现场宝箱上站有两个己方村民，得到Move。框选两名村民派矿，再由同一探险家右键同一宝箱得到Claim并领取100XP。Pick给单位的固定优先级高于宝藏；ContextOrder遇到己方村民时保持Move，所以不是模拟把合法Claim改写。

右键上下文应识别适用的交互目标，友方移动单位不能吞掉宝藏/采集点；左键仍需能选中遮挡建筑或资源的单位。敌军、迷雾、守卫、领取资格及距离继续由统一规则校验，不在输入层发免费奖励。
