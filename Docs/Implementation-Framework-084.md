# 084 · 河谷样板与完整玩法实施框架

以一张可以完整游玩的河谷样板串起地图、经济、战斗与运输，再把相同质量要求依次用于热带河湾、支流和河口

本框架承接原四段河图计划，原 A–D 历史实战里程碑保留原版本身份

2026-10-22用户要求暂缓400人验收，后续内容、美术、文明与AI开发继续推进，400人结果保留为未解决的已知限制，不再作为本轮内容推进的前置门槛

- 077／078 蜿蜒河谷岸形和水线、079 小队操作与付费运输、080 港船轮廓、081 热带河湾已有历史交付
- 082 支流和083河口是0.25.0未交付候选，现有本地文件不能算作完整交付
- 当前规则配置六文明，四经典文明核心机制已有实现，完整特色升级和广泛平衡仍需补足
- 62实际原400人验收失败，支流37／400、直河376／400陆军抵达，两图船只均12／12
- 183项专项通过属于62相同历史来源，不代表后续调度、画面或AI候选已经通过

## 顺序与依赖

1. 保留现有失败现场，完成局部运动与河岸画面的独立候选
2. 完成样板河谷的采集、升时代、建港、运输与战斗连续操作，小队规则验证与内容开发并行，400人验收暂缓
3. 依原顺序闭合热带河湾、支流、河口的玩法差异和AI水陆投资
4. 深化四个经典文明的实际路线，完成整局与性能检查，再冻结同源构建与私有交付

所有生产候选先经根任务审查再进入仓库，同一时刻只运行一个真实Unity Editor

每段的可见成果包括固定镜头对比、连续操作片段、可启动客户端和清楚的未完成项

## 移动职责

全局路线决定经过哪些区域与桥梁，桥口协调决定提前合流和通过次序，局部速度处理近处预测冲突，最终提交继续检查地形、桥道、身体、速度与坡度

共享路径或流场用于复用导航计算，不能单独作为无死锁保证

当前局部候选使用预测意图、切线与速度候选，属于本项目的有限避让模型，其通行与安全性由实际游戏世界测试核验

资料依据为[《帝国时代IV》GDC开发者分享](https://www.gdcvault.com/play/1027659/Pathing-in-Age-of-Empires)、[Supreme Commander 2开发者章节](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter23_Crowd_Pathfinding_and_Steering_Using_Flow_Field_Tiles.pdf)及[ORCA原论文](https://gamma.cs.unc.edu/ORCA/publications/ORCA.pdf)

这些资料各有同步运动、推挤或终点语义边界，未证实《帝国时代III》内部采用同一实现
