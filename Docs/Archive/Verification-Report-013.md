# 0.1.3 验证报告

本项目是 Unity 原生 I–III 开发版本，尚未通过用户提出的完整陆战与最终视听验收。以下明确区分实现、自动规则测试、真实客户端操作和未验证范围。报告在本机 2026-09-14 汇总；原始 XML/日志使用 UTC，日期可能为 2026-09-13。

## 实际工程与客户端

固定 Unity 6000.6.0f1（f7f8ed4d1e24）、URP 17.6.0、Input System 1.20.0、UGUI 2.6.0、Test Framework 1.8.0。真实 FrontierSkirmish.unity 场景与 Unity GameObject、Canvas、EventSystem、AudioSource 构成应用。macOS Apple silicon / Development / Mono / Metal 本机已构建、启动并检查；没有网页依赖。当前版本不是 LTS，选择与兼容性根据本机实际导入/构建/运行证据，详见 Environment.md。

验收机器：Apple M4 Pro（14 CPU 核、20 GPU 核）、48 GB RAM、macOS 26.5。默认 2560×1440 渲染，60 FPS 上限，vSync 关闭。不同构建的结果分别标版本，源码包不包含 Library 缓存。

## 自动规则与生命周期

26 个 EditMode 测试与 4 个 PlayMode 测试通过。XML 根节点 result=Passed、passed=total、failed=0；具体 UTC 时间与最终源码导入结果见同包 Evidence。自动测试不是玩家体验验收。

- 规则测试覆盖真实工作范围与采集入账、暂停不推进、人口预留/退款防重、资源耗尽后重新找点、75% 建筑取消退款与导航恢复、接收建筑消失后的时代奖励等待、科技保血量比例且不重复叠加、住房被毁保持已有单位。
- 船运覆盖机会与一次性卡防重、资源箱需要采集、接收建筑被毁等待、人口不足等待。
- 战斗覆盖重复命令不能重置攻击间隔、弹丸飞行中目标死亡、多标签最高倍率与对应抗性、范围伤害按每个受击者重算、建筑死亡释放人口和障碍且幂等。
- 导航覆盖阻挡/不可达/窄格通道/独立槽位，50 个混合单位真实移动至各自目的地，以及墙移除后重新通过。开发过程中曾出现 47/50 到达，修正到达容差、局部绕行与混合槽位间距后才通过；未用放宽断言隐藏未到达单位。
- PlayMode 通过实际 GameController 生命周期、暂停恢复和重开；同一次输入更新内的快速拖拽；UI 建造点击隔离；带完整修饰键状态的快速编队保存与调用。

## 原生普通玩家模式：已有消灭结算

Evidence/macos-manual-match.json 与事件 JSONL 来自 **0.1.2 / autoplay=false / speed=1**，真实菜单进入后人工分段发出命令。持续 567.908 秒（9 分 27 秒），AI 获胜，结束原因 match_finished；没有用认输替代这一局的消灭结算。

实际检查过单选、框选、双击同类、快捷定位、采集/耗尽转移、村民队列和资源支出、建造菜单不扣费/地图放置才扣费、庄园完工的人口和村民奖励、升级至时代 II、主动发送长枪兵船运、敌方攻城、驻扎与结算。原生画面另存 Captures。

这一局玩家采集 2062.3667 食物，支出 1100 食物，时代 II、1 次船运、5 次击杀、14 次损失。初始 300 食物加采集减支出与结算库存一致。事件中时代完成为 372.8135 秒，发卡 390.4146 秒、到达 425.4168 秒，间隔约 35.002 秒。点击结算的 PLAY AGAIN 后看到食物/木材/钱币恢复 300/300/100、时代 I、人口 6、XP 0、船运 0。

此局没有充分操作自己的混合军队和炮兵攻城，也没有证明玩家胜利路径、所有快捷键、全 UI 反迷雾泄露矩阵和平衡。因此“普通模式已经打到结束”和“全部核心体验已经验收”是不同结论。

## 0.1.3 界面与编队

主城卡牌明确显示资源箱数量、增援数量/人口、持续科技数值；DETAILS 面板显示配置与运行时共同提供的生命、攻击、标签、分类抗性、射程、间隔和目标加成。实际原生画面已检查。

组合键验证存在工具边界：原生 -frontierInputTrace 日志在工具请求 Ctrl+1 或 Command+1 时仅收到数字 1，没有 Ctrl/Meta 状态，因而不能据此宣布物理键盘组合键通过或游戏逻辑失败。合成完整输入的 PlayMode 通过。鼠标 GROUPS 面板和数字调用使用同一保存/调用方法。原生实际执行了保存 1 名村民到第 1 编队、切换城镇中心、按数字 1 恢复村民选择并定位，成功。画面见 Evidence/Captures/native-group-recall-013.png。最终检查还修正了按钮被销毁后悬停说明滞留的问题。

## 完整自动对局

规则层同系统 AI 对局（0.1.2）在 1183.058 秒模拟时间以玩家 1 获胜结束：双方时代 II/III，击杀 51/90，船运 4/6，44871 条事件。计算耗时 2.122 秒仅是无渲染模拟的运行时间，不能折算为游戏帧率。原始 automated-duel.json/JSONL 可追溯。

最终交付构建 0.1.3 的真实独立客户端以显式 8 倍自动验证模式运行，1113.575 秒模拟时间（18 分 33 秒）消灭结算。双方时代 II/III，击杀 39/78，船运 4/6，39667 条事件与报告一致。原始 Evidence/macos-autoplay-match.json、-events.jsonl 和 native-match-event-audit.json 保留。双方均使用正常资源/人口/生产规则，未启用高生命性能夹具。最终原生画面确认结算后可返回菜单。

本局实际生成长枪兵、火枪兵、骠骑兵、龙骑兵、散兵，以及铸炮厂；没有生成炮兵。因此不能把本局当作炮兵攻城验证。自动控制只由显式 -frontierAutoplay 启用，默认玩家模式不启用。此局启动期间还进行过干净工程 PlayMode 检查，不将其帧时间作为独立性能基准。自动对局不代替真人军队操作和声音验收。

## 性能证据边界

50/100/200/400 四档实际活动单位短样本来自 0.1.2 独立客户端；详情和原始 JSON 见 Performance-Report.md 与 Evidence/Benchmarks。每档 5 秒预热、20 秒采样，使用明确的高生命夹具保持开始/结束活动数量。单位数量是全场两个阵营实体之和，与人口值不同。

平均帧时间依次为 16.78、16.86、16.89、16.93 ms，P99 为 17.59、19.88、25.23、32.91 ms。有记录 GC 和尖峰，不能写为“400 单位全场稳定 60 FPS”，也没有 4K60、长时压力、完整窄口群体或其他硬件保证。导航/战斗计时来自模拟阶段采样，不是 GPU Profiler 数据。

## 干净导入与包装

先只复制 Assets、Packages、ProjectSettings、Docs、Tools 与说明文件到新目录，未提供 Library。Unity 恢复依赖后，EditMode 26/26 和 PlayMode 4/4 通过，并在该目录成功构建最终交付的 macOS app（Unity 报告 172626275 字节）。原始 fresh-editmode.xml / fresh-playmode.xml 与 build-receipt.json 保留。

构建工具重新生成了原生场景的对象 ID；将该实际构建场景同步回交付源码，保留原场景 meta GUID。最终 112 个 Assets/Packages/ProjectSettings 文件与已构建目录逐项 SHA-256 比较一致；详见 runtime-source-sha256.json 与 fresh-import-comparison.json。这不是二进制可复现构建或跨机器验证的声明。

源码包保留 Assets 及所有必要 meta、Packages、ProjectSettings、Docs、Tools，排除 Library/Temp/Logs/Builds/obj/UserSettings 等缓存；客户端单独打包并附许可。两个 ZIP 的 CRC、目录内容与 SHA-256 在包级验证记录中检查。
