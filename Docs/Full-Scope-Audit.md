## 0.2.0 版本边界补充

`ProgressionTests.cs` 已覆盖 `river`/`coast` 对局配置、MaxAge=5、25 张预置 deck、36 项科技相关路径、房价/村民钱币费用、Bank 上限和 Bank 被动收入；`SkirmishSetupTests.cs` 已覆盖菜单选择两个文明、I–V 年龄上限和重开后的配置保留。这些是 0.2.0 源码与自动化证据。0.1.3 的客户端截图和输入日志只能证明旧构建当时的可见行为；0.2.0 新构建有局部原生菜单双文明切换、25 张卡编辑分页、村民金币支付/退款、房价和暂停返回菜单证据；不等同完整人工经营、混合军队和五时代体验。

以下细项仍须分开验收：驻守进入/退出、驻守容量与建筑摧毁释放；炮兵部署/解除部署；适用单位的近战/远程模式切换；最小射程、范围伤害、弹道命中和目标死亡；双击同类、框选遮挡、Shift 队列和小地图下令；建筑预览与实际占地、施工多工人、取消退款和动态寻路；住房被毁后的超人口和生产出口堵塞；卡牌箱子实际采集、单位出生受阻、科技卡幂等和船运重复；三态迷雾下单位、目标、AI、小地图与事件提示一致性；AI 侦察、经济恢复、进攻撤退、扩张和可结束对局；从菜单到结算的 coast 与 river 人工整局；完整五时代客户端路径。

驻守相关必须分别检查：单位进入可驻守建筑、建筑容量上限、驻守后不可被普通目标选择、建筑被摧毁后的单位释放/伤害、手动撤出与集结点。炮兵相关必须分别检查：移动态、部署态、部署时间、解除部署、部署期间攻击限制和 UI 状态。近远程模式必须分别检查：切换是否保留目标、射程/最小射程、攻击冷却是否被重置、目标离开范围后的重选。经济与船运必须分别检查：资源箱实际采集、资源耗尽转移、人口预留、住房摧毁、接收建筑缺失、出生点堵塞、重复卡去重和研究效果对既有/新单位的一致性。

400单位窄口首次85未抵达，保持原有时限和断言修复后通过；当前0.2.1规则与导航54/54、场景8/8。证据见 Verification-0.2.1 与 Navigation-020.md，不能由此宣称原生400实体帧率与全部通行组合达标。

0.2.1新增贸易与宝藏合同见 Landmarks-Implementation.md。首次原生检查观察到贸易路线穿透迷雾和探险家过远自动追击，修订版已构建；锁屏期间无法完成修订后画面与鼠标检查，不能记为原生验收通过。贸易垄断、探险家倒地/赎回、完整守卫/宝藏类别仍未实现。

海战、多人大地图、联网、战役和地图编辑器是用户明确允许在阶段 D 之后再考虑的扩展（本文记为 D'），不是本轮要求必须交付的网络产品；它们也不能反向掩盖陆战核心未验收。

本项目不得把“代码存在、配置完整、自动测试通过、自动对局结束、Console 无报错、生成截图或构建成功”单独标为完成。Stage C/完整陆战的 completion gate 是：本地独立客户端中，玩家能从菜单开始真实 coast 镜像对局，完成侦察、采集、建造、升级、发卡、组织军队、交战、攻城和胜负结算；随后以相同证据标准开放 river 与 IV–V。每一项都要记录通过、失败、受阻和未检验，并补足 UI、画面、声音、操作手感、性能和从开局到结算的人工证据。
