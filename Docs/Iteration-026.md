# 0.2.6：驻扎防守与原生界面输入验证（开发检查点）

本轮范围与验收合同，2026-09-14；不代表阶段 B、C 或 D 完成。

先保留 0.2.5 全部封存材料。当前重点是普通资源玩家完整对局中的可操作性与驻扎防守。

- 驻扎火力：普通 TC 陆上攻击采用项目契约 9 × min(有效本方驻扎村民数,10)，3 秒攻击周期，50 总容纳，16 项目世界单位射程。9/10/3/50 有社区二级出处，尚未指定决定版补丁游戏内实测；16 为既有压缩地图尺度的项目取值。空驻扎不射击；非村民不增加火力；已发射弹道保持发射时快照；驻扎变化不重置冷却。模型分开保存容量和贡献火力的上限。
- 官方 Update 56860 的 10 人封顶仅直接支持墨西哥 Palace of Iturbide 卡炮击，不能把本轮普通攻击公式写成官方确认。
- 原生主城 NEXT 观察：先核对原始鼠标位置、真实 UGUI 点击和发送事件；不能因为最终出现了船运就推断界面错误。覆盖页面重建、卡牌解锁和快速点击。
- 批量生产：增加可见的单个/批量选择入口，费用、人口、禁用原因与命令使用同一个请求数量。仍遵守正常支付和生产规则。
- 玩家对局必须真实完成侦察、采集、住房、升级、发卡、训练军队、交战、攻城与结算后，才能记为核心操作闭环通过。

参考：[社区 TC 数据](https://ageofempires.fandom.com/wiki/Town_Center_(Age_of_Empires_III))；[官方 56860](https://www.ageofempires.com/news/aoe-iii-de-update-56860/)。二级资料未提升为已核实的原作规则。

当前已构建检查点 GUID 为 `1d6f91c80312451fbdd17cde193d5d45`，Build.log 报告客户端大小 `172858362` bytes。该候选构建前完成87项EditMode与53项PlayMode测试，构建后追加两项结算输入回归并完成55/55全量PlayMode；原生第三候选仅完成 136 秒的输入与驻扎局部检查并从菜单退出，尚无最终候选的人工完整玩家对局结算。因此阶段 B 核心操作闭环、完整陆战版本和阶段 D 均未通过验收。

## 开发过程中的实际发现

- 旧驻扎规则局部 8 项测试全部失败；新实现 8/8。测试驱动真实 World.Tick 和驻扎/释放指令，没有向不接受单位命令的建筑伪造 Attack 指令。
- 旧 UGUI 主城逻辑在修正测试夹具后 4/4：NEXT 两次不发卡、禁用卡解锁再翻页、按 NEXT 后移到卡牌释放不发卡、原生卡牌坐标再 NEXT 恰好一船运并到第二页。初次 1/4 是批处理编辑器无焦点及 640×480 与原生 16∶9 坐标转换错误，不是客户端回归。夹具才设置 IgnoreFocus 并恢复，不改变玩家客户端焦点行为。
- 0.2.5 原生日志的 t=559.1626 收到 (1008,415)，换算截图逻辑 (504,544.5)，落 Food Convoy 2；t=559.2542 收到 (1002,212)，对应 (501,646)，落 NEXT。原生输入时间不是暂停可变的 World.Time。桌面工具为何首个请求点与收到的点不同尚不确定；现有证据不足以称 UGUI 翻页误发。
- 新批量 UI 在批处理默认 640×480（4∶3）中暴露了右端按钮超出屏幕。CanvasScaler 改为 Expand，保证最小参考画布 1600×900 完整可容纳，16∶9 默认外观不变。随后 7 项真实 UGUI 测试全部通过，包括按整批支付/预留/退款、整批资源或人口不足禁用、首选建筑队列满时调度另一座同类建筑。
- 批量数量沿用项目既有 1..batch 截断规则，一批一个生产槽、按单位生产时间完成整批；属于项目生产规则，未声称与原作所有文明批量行为等价。界面未增加所有建筑队列汇总；仍显示第一所选建筑的队列，生产请求可分配到其他已选同类建筑。
- 输入诊断使用可选 -frontierInputTrace，新增 UGUI 语义/位置/模拟时间，并去掉每条原始输入附带的堆栈；正常游戏不输出这类诊断。

## 原生客户端之后追加的输入修复

第一候选客户端（构建成功 172853495 字节）的正常资源镜像检查确认开局采集、训练、庄园和守卫交战，但在升级面板反复出现有效点击取消。此局中止用于排查；不能作为完整对局通过。日志原始抬起 (1612,282)，UGUI 处理时却使用 (299,1375)，命中资源栏。第一次点击卡牌的旧 0.2.5 记录仍只能说明其原生首个坐标在卡牌上，不能与这条新故障混为同一已证实原因。

新增两个测试：NEXT 内抬起后同次更新移到资源栏；NEXT 完整按下/抬起后同次更新移到卡牌。旧路径 0/2，分别丢失点击和误发送卡牌；先前仅测试最终位置未变化的路径不够完整。

修复使用 UiPointerDispatcher 与世界指令共用已排序的原生事件流。Unity 原生 EventSystem、GraphicRaycaster、Button 继续执行实际界面交互；InputSystemUIInputModule 保留悬停与键盘导航，离散鼠标点击由每次按下/抬起的位置派发，避免帧末鼠标位置替换历史点击。按住按钮时不重建操作栏，旧按钮在销毁前立即停止响应。UI 按钮转换保留之后的 UI 事件；世界指令仍受短暂屏障保护。另加同更新内连续两次翻页与长按跨周期刷新测试。

当时第二候选的完整测试与重新构建/原生检查仍需补齐；这是历史记录，后续结果见本文件的最终候选状态。第一次客户端证据放在 Verification-0.2.6/Regression/First-client-attempt。

历史中间候选的 PlayMode 为 50/50（UTC 2026-09-14 03:20:12）。连续页面创建后，新 UGUI 图形要经过画布渲染才能用于下一次原生射线命中；保留剩余事件到下一帧处理，因此该候选的连续翻页测试等待了明确的帧边界，而非丢弃或重发点击。首次过早断言及诊断日志保留。历史中间候选的 EditMode 为 87/87（UTC 02:52:50）；最终候选结果以本文件前面的当前验证结果和对应 XML 为准。


## 第二候选的原生诊断局（2026-09-14）

Build GUID `2cda940bbf26467a961fab26cfab1ff4`；Coast 镜像、seed 314159、上限 III、普通资源，autoplay=false、模拟速度1。实际进行了采集、共同施工、时代 II、村民与火枪兵船运、两次5火枪和一次5长弓批量训练、攻击移动与小地图指令，随后在672.683秒暂停后主动认输，结算和返回菜单均实际检查。重新开局显示300F/300W/100C、6人口、Age I、XP0/150、Ship0。此局属于诊断局，未完成玩家Age III与炮兵攻城，不能列为完整核心对局通过。

本局曾出现两次GROUPS位置点击只命中Orders and economy。待分别检验：军队第一选中对象死亡造成按钮位置变化，以及操作栏在点击同帧刷新造成的不可点击窗口。输入日志已记录edge坐标与raycast，不能仅据父面板命中认定为坐标错派。先追加固定选中对象、强制真实周期刷新分支的InputSystem回归，再决定修复。第二次GROUPS请求前后第一对象已从火枪兵变成长弓兵，旧位置失效本身可能是合理解释。

固定军营选择、强制真实周期刷新分支、真实InputSystem完整按下/抬起回归在第二候选代码上失败（Periodic-ui-before.xml，0/1，未出现TRAIN: BATCH）。修复将所有结构刷新记录到创建帧，输入FIFO在画布仍属创建帧时不取出事件，下一帧再派发；不修改模拟规则、费用或攻击时间。单位类型变化造成按钮位置变化仍为单独的界面易用性问题，不冒充已解决。

同帧刷新修复后的12项主城/批量/指针场景测试全通过。另将混合军队的公共DETAILS/GROUPS操作设为固定栏位作为主动界面改进，避免第一名火枪兵死亡后切成长弓兵时按钮左移。先以真实伤害杀死第一选中单位，断言剩余单位的GROUPS屏幕位置不变，再点击该位置验证面板打开。此项是项目操作契约，不是原作规则结论。

完整输入回归发现全局画布等待会让14项世界/键盘操作多等一帧，完整52项中38项通过。该候选被拒绝（Regression/PlayMode-before-ui-only-gate.xml）。改为只检查UI图形矩形覆盖范围内的左键事件，世界点击、小地图和键盘仍立即按FIFO处理；图形矩形仅用于保留输入，不替代GraphicRaycaster选择按钮。等待中的事件通过Peek保留原顺序。

52项完整PlayMode先已全通过，随后针对独立审查中的混合输入边界追加“同帧小地图点击后再点重建操作栏”的回归。该回归先失败：小地图路径误清除了尚未完成渲染的UI dirty状态。修复限定仅在创建帧之后才能清除dirty。队首UI事件等待时，后续事件同样保留FIFO顺序等待；不声称绕过待处理UI的键盘/世界事件仍在同帧执行。

## 最终客户端整局与结算入口补查

这两项测试在最终客户端构建之后追加；没有改动运行时输入文件或重新构建。全量PlayMode55/55。原始跟踪重跑确认失败请求实际从按钮外按下；当按下和抬起都收到正确按钮位置时，MAIN MENU真实触发并返回菜单。详细坐标与证据见Native-Verification-026.md；无需运行时修改。
