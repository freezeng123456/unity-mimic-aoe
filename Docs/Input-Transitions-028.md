# 0.2.8 输入转换：契约、诊断与验证

本页的交互契约属于 P（本项目规则），不声称是已核实的《帝国时代 III：决定版》内部输入实现。触发来自封存0.2.7客户端的正常玩家局：原生日志记录ESC后T/V按下，画面却仍保持旧选择。Ctrl/Command+数字得到save=False是另一项待核实观察，本轮没有修改修饰键捕获。

## 实现前确定的项目契约

- 主城、建造或其他模态面板关闭后，后续键盘事件按到达顺序立即作用于新的界面状态。
- 0.22秒转换保护用于防止鼠标穿透，不应把所有键盘事件一起丢弃。
- ESC之后同更新周期中已排队的右键不能成为地面命令；旧鼠标按下/抬起边沿一起丢弃。
- 面板保持打开或对局暂停时，世界快捷键被消费并忽略，不能在稍后关闭面板时重新执行。
- 开始新局、重新开始、返回菜单和应用失焦仍全量清空旧输入；新局清空编队和选择。
- UGUI点击保留既有FIFO与Canvas布局等待，不能跳过尚未重建的按钮判定。
- 不改动模拟速度、攻击冷却、经济、人口、科技、卡牌、AI或规则数值。

## 先提出并分步检验的假设

1. ESC关闭面板调用全量Clear，把它后面的T/V一起删除。如果保留队列中后续键盘边沿、仅删除指针边沿，同批次ESC→T/V应恢复。
2. 即使下一次更新才按键，0.22秒时间门控也过滤所有键盘事件。如果门控只作用于指针，真实关闭按钮后T、建造按钮后G应恢复，但仍被Clear删除的同批次ESC→T/V不会恢复。
3. Canvas重建等待可能独立影响事件顺序。如果前两处修正后真实按钮用例仍失败，需要检查布局等待和测试观察时点，不能先假设是规则或键盘状态缓存。

先仅调整时间门控，结果准确符合第二项预测；再增加DiscardPointerEdges，修复剩余ESC用例。保留键盘FIFO时不重置已捕获的物理鼠标按下状态，避免在按钮实际仍按住时伪造新的down。生命周期/focus仍调用全量Clear。
